# results/ scan (before shipping results/ with the project)

Scope: every file under `results/` (43 files: 29 json, 13 csv, 1 lock, including four per-run subfolders). Checked for case text, case titles, query text, fact or issue sentences, and keys or tokens. No case text is copied into this note.

## Flagged and fixed
| File | Field | Reason | Action |
|---|---|---|---|
| results/role_profile.json | `distinctive_stems_Court_Disclosure_vs_Court_Reasoning`, `distinctive_stems_Court_Reasoning_vs_Court_Disclosure` | word stems taken from case text; they can contain party names | the two fields were removed from the shipped file (nothing in app, scripts or tests reads them; the API only passes the file through). The full file is kept outside the zip in `data/role_profile.full.json` and is regenerated by `scripts/profile_roles.py` |

## Reviewed and kept
- Long strings (12 to 29 words) in `and_benchmark.json` (`note`), `b2_ablation_dev.json` / `.csv` (`row_notes`, `row` labels), `crawl_sim.json` (`graph`, `note`, `targets`), `efficiency.json` (`note`), `zone_matrix.json` (`learner`, `note`): author-written descriptions of the experiment, not case text.
- Matches for "token" in `b1_dev_rows.json`, `data_inspect.json`, `index_report.json`, `statute_bridge.json`: key names that count indexed tokens (for example `tokens_all_zone`), not credentials. A search for key-like strings (`sk_...`, `hf_...`) found nothing.
- `data_inspect.json` holds column names only. `b2_explain_example.json`, `statute_bridge.json` and the per-run `per_query.csv` files hold ids, statute ids, counts and scores only.
- `final.lock` holds a run id and a time.

## Result
One file was changed; no whole file had to be excluded. `results/` ships with the project and contains aggregates, ids and scores only.
